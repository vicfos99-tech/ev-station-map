# 요구사항: 배포 전 비밀값 검사가 시험용 가짜 키를 알아보게 하기

출처: 2026-11-17 배포 중 막힘. `tools/push.sh` 가 부르는 `tools/check_secrets.py` 가 잠긴 테스트 `tests/test_r2_fresh_relay.js` 242행의 시험용 가짜 키 `serviceKey=AbCdEfGhIjKlMnOpQrSt` 를 진짜 키로 보고 올리기를 막는다. 잠긴 테스트는 고칠 수 없다.

## 범위 (작은 단위 — 부분 하나)
- 프로젝트 `10_프로젝트/ev-charge-planner/`. 고칠 곳은 `tools/check_secrets.py` 와 새 파일 `tools/secret_allow.txt` 뿐. `web/`·잠긴 tests 는 고치지 않는다. 표준 라이브러리만, 파이썬 3.10.
- **시험 자료 두는 곳:** 테스트 세션은 `tests/test_<부분>_` 로 시작하는 파일만 만들 수 있다. 시험 자료는 테스트 파일 안이나 `tmp_path` 에. 새 테스트 글 3000자 이하.

## 바꿀 것
1. `tools/secret_allow.txt`: 한 줄에 하나, **허용할 가짜 글 전체**(예: `serviceKey=AbCdEfGhIjKlMnOpQrSt`). `#` 로 시작하는 줄과 빈 줄은 무시. 처음 내용은 위 한 줄과 설명 주석.
2. 검사: 파일마다 PATTERN 에 걸린 **모든** 글을 찾아, 그 글이 허용 목록의 어느 줄과 **글자까지 같으면** 넘어가고, 하나라도 허용 목록에 없으면 지금처럼 "키처럼 생긴 글자가 있다". 부분 일치·접두 일치는 허용하지 않는다(진짜 키가 가짜 글로 시작해도 걸려야 한다).
3. 환경변수 값 검사(`SECRET_ENVS`)는 허용 목록과 상관없이 그대로(허용 목록이 진짜 키 값을 담고 있으면 그 줄은 무시하고 경고 한 줄 — 값은 찍지 않는다).
4. 허용 목록 파일이 없으면 지금과 똑같이 동작한다.

## 수용 기준
- 가짜 글만 든 파일 → 통과. 같은 파일에 허용 안 된 `serviceKey=` 키가 하나 더 → 실패.
- `serviceKey=AbCdEfGhIjKlMnOpQrStXYZ123`(허용 글로 시작하지만 더 긴 것) → 실패.
- `bot123456:...`·`KakaoAK ...`·`-----BEGIN ... PRIVATE KEY` 는 허용 목록에 없으면 지금처럼 실패.
- 허용 목록 없음 → 지금 결과와 같음. 출력 어디에도 걸린 글의 값이 찍히지 않는다(파일 이름만).
- 저장소 전체에 돌리면(지금 커밋된 파일들) 통과한다.
- 앞의 잠긴 테스트가 모두 통과한다.
