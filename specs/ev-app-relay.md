# 요구사항: 충전 길잡이 앱이 공공 데이터를 중계에서 읽게 바꾸기

출처: 2026-11-16 묘성 "데이터 받아오는 부분 모두 이 데이터 중계 앱에서 받아오게 수정". 묘성이 정한 구조: 집 PC 가 받아 밖으로 올리기만 하고, 앱은 거기서 **읽기만** 한다. 앱은 전면 수정이 아니라 **데이터 받는 곳만** 바꾸고, 폰 직접 받기는 **예비로 남긴다.** 앱의 지도 풍선에는 글자를 HTML 이 아니라 글자로만 넣는다(이중 방어).
앞 실행(`specs/ev-data-relay-2.md`)이 만든 파일 모양을 읽는다. 그 모양은 이 프로젝트의 `ref/relay_format.md` 와 `ref/relay_sample/` 에 복사해 둔다(실행 전).

## 프로젝트와 언어
- 프로젝트는 지금 앱 `10_프로젝트/ev-charge-planner/`. 바꿀 곳은 `web/` 의 자바스크립트다. **기존 파이썬 테스트(tests/, 잠김)와 `web/test/` 대조 스크립트는 고치지 않고 계속 통과해야 한다.**
- 새 코드는 새 파일 `web/relay.js`(브라우저 전역 `EvRelay`, Node 에서는 `require`)에 순수 함수로 모으고, `app.js` 는 부르는 곳만 바꾼다.
- 테스트: `tests/test_relay_js.py` 같은 pytest 파일이 같은 부분 이름의 JS 시험 파일(`tests/test_<부분>_relay.js`)을 `node` 로 불러 결과를 본다(node 는 PC 에 있다). 네트워크는 가짜 fetch 로.
- **p0 = 테스트 틀(pytest 에서 node 를 부르는 도우미, 가짜 fetch — 모두 `tests/test_p0_` 로 시작하는 파일)을 맨 앞 부분으로 따로 둔다.** **시험 자료 두는 곳(지휘 스크립트 규칙):** 테스트 세션은 `tests/test_<부분>_` 로 시작하는 파일만 만들 수 있다(그 밖의 파일은 지휘 스크립트가 되돌린다). 그래서 시험 자료는 그 부분 테스트 파일 안에 글자로 넣거나 `tests/test_<부분>_data_*.json` 같은 이름으로 둔다. `tests/data/` 같은 따로 된 폴더는 쓰지 않는다. 테스트 세션은 `web/` 을 고칠 수 없다.
- **테스트 크기:** 지휘 스크립트는 교차 검증에 한 부분의 테스트 파일을 합쳐 앞 60000자까지만 보여 준다. 그래서 부분마다 `tests/test_<부분>_` 파일 전부 합쳐 45000자 이하로 쓴다(같은 모양 사례는 표로 묶는다).
- 다 바꾼 뒤 `node build.js` 로 `dist` 가 만들어져야 한다(빌드 성공을 테스트로 본다). 배포(push)는 실행 뒤 대화에서 한다.

## 기능

### 1. 중계 주소
- 묘성 11/16: 중계가 일정 간격으로 **앱이 올라가 있는 웹페이지(GitHub Pages)** 의 `relay/` 폴더를 갱신하고, 앱은 사용자가 원할 때(새로 받기·지도 열기) 그 갱신된 파일을 보여 준다.
- 그래서 기본 중계 주소는 앱 사이트의 `relay/` 폴더다: 웹에서 열면 페이지 주소 기준 `./relay/`, 안드로이드 앱 안(페이지 주소가 `http(s)://` 가 아님)에서는 상수 `https://vicfos99-tech.github.io/ev-station-map/relay/`. 이 상수는 `relay.js` 맨 위 한 곳에 둔다.
- '내 차·할인' 화면에 '공공 데이터를 중계에서 받기' 켜기/끄기(기본 켬)와 주소 바꾸기 칸(빈 값 = 기본 주소). 폰 localStorage 에만 저장. **끄면 지금과 똑같이** 폰이 직접 받는다(이 경우 동작이 한 글자도 안 바뀌는지 기존 대조로 확인).
- 바꾼 주소는 `https://` 로 시작해야 한다. 아니면 저장하지 않고 이유를 보여 준다.

### 2. 휴게소 '새로 받기'
- 중계가 켜져 있으면: `meta.json` → `routes.json`(노선) → 지금 노선에 든 휴게소의 `status/rest/<id>.json` 을 읽어 상태를 덮어쓴다. 공공 데이터 키가 없어도 된다.
- 읽기에 실패하면(연결·404·모양 틀림) 폰에 공공 데이터 키가 있을 때만 지금 방식(직접 받기)으로 넘어가고, 화면에 "중계에 연결하지 못해 직접 받았어요"를 보여 준다. 키도 없으면 오류 글.

### 3. 지도 주변 충전소
- 중계가 켜져 있으면: 시군구마다 `stations/<zscode>.json` + `status/<zscode>.json` 을 읽어 지금 `EvAround` 가 만드는 충전소 모양과 **같은 모양**을 만든다(그래서 그리기 코드는 그대로). 중계 파일은 ⚠ 10분마다 갱신되므로 지도에서는 3분마다 `status/<zscode>.json` 만 다시 읽는다(바뀐 게 없으면 그대로).
- 실패하면 2 와 같은 예비 규칙.

### 4. 오래된 상태 (안전)
- 상태 파일의 `at` 과 지금 시각 차이가 ⚠ 15분 넘으면 화면에 "N분 전 상태" 를 보여 준다. ⚠ 30분 넘으면 그 상태를 **빈자리로 세지 않는다**(상태 미확인으로 본다) — 빈자리를 실제보다 많게 보이면 안 된다.
- `meta.json` 의 `ok` 가 false 면 그 이유를 짧게 보여 준다(키·주소는 보여 주지 않는다).

### 5. 글자 안전
- 중계에서 받은 모든 글(충전소 이름·업체·제조사·주소)은 화면에 넣을 때 `textContent` 또는 HTML 이스케이프를 거친다. 지도 풍선(Leaflet divIcon 의 html)에 들어가는 글은 이스케이프 함수를 반드시 거친다. 테스트: 이름이 `<img src=x onerror=alert(1)>` 인 충전소의 풍선 html 에 `<img` 가 없다.

### 6. 그대로 두는 것
- 카카오 길찾기·장소 찾기, 오픈스트리트맵 장소 찾기: 폰에서 그대로(목적지마다 달라 중계가 미리 받을 수 없다).
- 화면 배치, 노선 계산, 길찾기 엔진(navi.js), 지도 그리기.

## 원칙
1. 중계를 끄면 지금과 같다. 2. 오래된·모르는 상태를 빈자리로 세지 않는다. 3. 키·주소를 오류 글·로그에 넣지 않는다.

## 통합 흐름 (가짜 fetch)
중계 끔 → 기존 대조 통과 → 중계 켬(기본 주소) → 새로 받기가 중계 파일만 읽음(공공 데이터 주소 호출 0번) → 지도 주변이 같은 모양 → 상태 `at` 을 40분 전으로 → 빈자리 0으로 셈 → 중계 404 + 키 있음 → 직접 받기로 넘어가고 안내 글 → 이름에 태그 → 풍선 html 에 태그 없음 → `node build.js` 성공.
