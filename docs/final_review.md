  - `warn_rc1`: 경고만 있고 실패 줄이 없으면 종료 코드 1. 계획 D6 "경고만으로는 종료 코드가 바뀌지 않는다"가 잠기지 않았다(계획서 182행이 "실제 배치에서는 만들 수 없다"고 밝힌 갈래).
  - `min_len_1`: 환경변수 값 8자 문턱을 1자로. 원래 있던 규칙이고 이번 테스트 대상이 아니다. 테스트의 가짜 값이 모두 8자 이상이라 가려지지 않는다.
  - `allow_cwd_abs`: 허용 목록 자리를 "도구와 같은 폴더" 대신 "현재 폴더의 `tools/`"로. 테스트가 늘 저장소 루트에서 돌려서 둘이 같다. D4 가운데 "루트의 같은 이름 파일은 안 쓴다"만 잠겼다(S5).
  - `allow_env_checked_off`: main 이 `.md` 파일을 검사에서 뺌. 실제 저장소 테스트는 "통과"만 보므로 덜 보는 쪽으로 틀린 구현은 못 잡는다. 임시 저장소 흐름에는 `.md` 가 없다.
- **T4 main 을 거친 bot 토큰·`KakaoAK`·개인 키 블록 흐름(S4)과 환경변수 값만 걸린 파일(S8)은 잠긴 테스트에 없다.** 수용 기준 3 은 `count_keys` 수준(a1 기준 8)으로만 잠겼다. 지금 구현은 P4 로 맞다.
- **T5 허용 목록은 걸린 글만 보고 파일은 보지 않는다.** 허용 글은 어느 파일에 몇 번 나와도 넘어간다(요구사항대로). 특히 개인 키 블록은 걸린 글이 머리(`-----BEGIN … PRIVATE KEY`)까지뿐이라, 그 머리 한 줄을 허용 목록에 적으면 같은 종류의 **모든** 개인 키 파일이 통과한다(P5: (0, 1)). 계획 D5 에 적혀 있으나 위험으로는 적지 않았다.
- **T6 허용 줄을 잘못 적으면 말없이 안 듣는다.** 줄 끝에 주석을 붙인 줄(`가짜 글  # 설명`), UTF-16 으로 저장한 파일, CR 만으로 줄을 나눈 파일은 경고 없이 허용이 안 된다(P5). 막는 쪽으로 틀리므로 안전하지만, 그때 나오는 글은 "키처럼 생긴 글자가 있다"뿐이라 까닭을 찾기 어렵다.
- **T7 git 이 추적하지 않는 허용 목록.** `tools/secret_allow.txt` 를 커밋하지 않고 두면 허용은 듣는데 그 파일 자신은 검사받지 않는다. 그 안에 환경변수 값이 든 줄이 있으면 경고만 나오고 종료 코드는 0 이다(코드 읽기 — 계획서 182행이 "다루지 않는다"고 했다. P6 의 해당 사례는 위의 잡음 때문에 종료 코드로 확인하지 못했고 경고 줄과 값이 안 찍히는 것만 확인했다).
- **T8 실제 올리기는 확인하지 않았다.** 검사가 통과하는 것까지만 봤다. 이 검수 문서와 뒤에 쓰일 보고서도 추적 파일이므로, 올리기 직전에 `py tools/check_secrets.py` 를 한 번 더 돌려야 한다(이 문서는 쓴 뒤 전체 테스트로 확인했다 — 맨 끝 절).

## 5. 묘성이 정해야 할 것

1. **D1 허용 목록 둘째 줄(`serviceKey=AbCdEfGhIjKlMnOpQrStXYZ123`)을 둘지(Q1).** 권고: **둔다.** 진짜 키가 아니라 요구사항 문서가 예시로 적은 글이고, 지우려면 `specs/ev-secret-allow.md` 17행과 `docs/plan.md` 의 여러 곳을 띄어 적게 고쳐야 한다. 규칙 자체는 테스트로 잠겨 있다.
2. **D2 `.gitattributes` 에 `tools/secret_allow.txt text eol=lf` 한 줄을 넣을지(T1).** 권고: **넣는다.** 안 넣으면 이 PC 나 같은 설정의 PC 에서 새로 clone 하는 순간 테스트 1개가 실패한다. 넣은 뒤 새 clone 에서 전체 테스트를 한 번 돌려 확인한다. 코드가 아닌 설정 파일 한 줄이라 직접 할지 지휘 스크립트로 할지도 함께 정한다.
3. **D3 넘어간 수 줄(Q3)과 "잠긴 테스트가 저장소 전체를 본다"(T2)를 받아들일지.** 권고: 둘 다 받아들인다. 대신 앞으로 요구사항·문서에 가짜 키 예시를 적을 때는 글자 그대로 적지 말고 띄어 적는다는 규칙을 요구사항 틀에 한 줄 넣는다(이번 Q1 이 그렇게 생겼다).
4. **D4 허용 목록에 줄을 더할 때의 규칙(Q5·T5).** 도구는 이 PC 환경변수 값이 글자 그대로 든 줄만 막는다. 인코딩 꼴 키, 다른 PC 의 키, 개인 키 머리는 못 막는다. 권고: 허용 목록은 묘성이 diff 로 보고 넣는 파일로 두고, 세션이 스스로 줄을 더하지 않게 한다. Q4(하이픈 등이 이어지는 글)는 실제 키 모양에서는 생기지 않으니 그대로 둬도 된다.
5. **D5 검증 세션(P2·P3).** 검증 세션이 기록 `.md` 를 쓰지 않고 변이 실행 수 없이 pass 를 낸 것, 검증 B 가 sonnet 으로 돈 것이 뜻한 바인지 지휘 스크립트 설정에서 확인한다.
6. **D6 올리기.** 검사는 이제 통과한다. `bash tools/push.sh` 는 이 세션이 돌리지 않았다.
